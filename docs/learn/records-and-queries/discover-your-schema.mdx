# Discover your schema

RushDB is **self-aware** — it continuously understands its own structure: labels, field types, value distributions, relationships, and semantic search readiness. The `db.ai` schema methods expose this as either Markdown (for LLM injection) or structured JSON (for schema UIs, autocomplete, or property-ID lookups).

---

## What the schema contains

The schema is RushDB's always-current answer to "what does this project's data look like?" — computed from the graph itself, never declared upfront.

| Component                       | Description                                                                                             |
| ------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **Label inventory**             | All label names in the project with record counts, largest first                                        |
| **Property manifest per label** | Property ID, name, type, whether it holds arrays, how many records have it, and either sample values (strings, booleans) or a min–max range (numbers, datetimes) |
| **Relationship map**            | Which labels connect to which, via which relationship type, in which direction, how many relationships, and the properties they carry |
| **Semantic index status**       | Which properties have vector indexes and whether they are ready for `db.records.vectorSearch()`         |

Building an AI agent? [Schema Self-Awareness](../agent-memory/schema-self-awareness.mdx) shows what the rendered output looks like and how to inject it into LLM context.

## Get schema as Markdown

The **recommended format for LLM context injection** — compact, token-efficient, and ready to paste into a system prompt.

<Tabs groupId="programming-language">
  <TabItem value="python" label="Python" default>

`db.ai.get_schema_markdown()`

```python
from rushdb import RushDB

db = RushDB("RUSHDB_API_KEY")

# Full schema as a Markdown document
response = db.ai.get_schema_markdown()
schema = response.data

# Scope to specific labels
order_response = db.ai.get_schema_markdown({"labels": ["Order"]})

# Recalculate now instead of using the cached schema (RushDB Cloud)
fresh_response = db.ai.get_schema_markdown({"force": True})
```

  </TabItem>
  <TabItem value="typescript" label="TypeScript">

`db.ai.getSchemaMarkdown()`

```typescript
// Full schema as a Markdown document
const { data: schema } = await db.ai.getSchemaMarkdown()

// Scope to specific labels
const { data: orderSchema } = await db.ai.getSchemaMarkdown({
  labels: ['Order']
})

// Recalculate now instead of using the cached schema (RushDB Cloud)
const { data: freshSchema } = await db.ai.getSchemaMarkdown({ force: true })
```

  </TabItem>
  <TabItem value="shell" label="Shell">

`POST /api/v1/ai/schema/md`

```bash
# Full schema
curl -X POST https://api.rushdb.com/api/v1/ai/schema/md \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $RUSHDB_API_KEY" \
  -d '{}'

# Scoped to specific labels
curl -X POST https://api.rushdb.com/api/v1/ai/schema/md \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $RUSHDB_API_KEY" \
  -d '{"labels": ["Order"]}'

# Recalculate now instead of using the cached schema
curl -X POST https://api.rushdb.com/api/v1/ai/schema/md \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $RUSHDB_API_KEY" \
  -d '{"force": true}'
```

#### Request body fields

| Field    | Type       | Required | Description                                                                  |
| -------- | ---------- | -------- | ---------------------------------------------------------------------------- |
| `labels` | `string[]` | no       | Restrict output to specific labels. Omit (or pass `[]`) for the full schema. |
| `force`  | `boolean`  | no       | Recalculate now instead of serving the cached schema (RushDB Cloud).         |

  </TabItem>
</Tabs>

## Get schema (structured JSON)

Returns the same schema as a structured array — useful for schema UIs, autocomplete, or looking up property IDs for `db.properties.values()`.

<Tabs groupId="programming-language">
  <TabItem value="python" label="Python" default>

`db.ai.get_schema()`

```python
# List all labels with counts
response = db.ai.get_schema()
for item in response.data:
    print(f"{item['label']}: {item['count']} records")

# Scope to specific labels
book_response = db.ai.get_schema({"labels": ["Book"]})
book_schema = book_response.data[0]

# Get property ID for value enumeration
genre_prop = next(p for p in book_schema["properties"] if p["name"] == "genre")
genres = db.properties.values(genre_prop["id"])

# Identify semantically searchable properties
indexed = [p for p in book_schema["properties"] if p.get("vectorIndexes")]
# indexed[0]["vectorIndexes"][0]["status"] == "ready" → queryable with db.records.vector_search()

# Recalculate now instead of using the cached schema (RushDB Cloud)
fresh_response = db.ai.get_schema({"force": True})
```

  </TabItem>
  <TabItem value="typescript" label="TypeScript">

`db.ai.getSchema()`

```typescript
// List all labels with counts
const { data: schema } = await db.ai.getSchema()
for (const item of schema) {
  console.log(`${item.label}: ${item.count} records`)
}

// Get property ID for value enumeration
const {
  data: [bookSchema]
} = await db.ai.getSchema({ labels: ['Book'] })
const genreProp = bookSchema.properties.find((p) => p.name === 'genre')
const { data: genres } = await db.properties.values(genreProp.id)

// Identify semantically-searchable properties
const indexed = bookSchema.properties.filter((p) => p.vectorIndexes?.length)
// indexed[0].vectorIndexes[0].status === 'ready' → queryable with db.records.vectorSearch()

// Recalculate now instead of using the cached schema (RushDB Cloud)
const { data: fresh } = await db.ai.getSchema({ force: true })
```

### TypeScript types

```typescript
type SchemaItem = {
  label: string
  count: number // records with this label; items are sorted by count, largest first
  properties: SchemaProperty[]
  relationships: SchemaRelationship[]
}

type SchemaProperty = {
  id: string // use with db.properties.values(); the same name and type share one ID across labels
  name: string
  type: string // 'string' | 'number' | 'boolean' | 'datetime' | 'null'
  recordsCount?: number // records of this label that have the property
  isArray?: boolean // true when records store the property as an array of values
  values?: Array<string | number> // strings: up to 10 samples; booleans: ['true', 'false']
  min?: number | string // numbers and datetimes (ISO 8601); alphabetical on non-array strings and booleans
  max?: number | string
  /** Present when the property has vector indexes; a 'ready' one is queryable with db.records.vectorSearch() */
  vectorIndexes?: SchemaVectorIndex[]
}

type SchemaVectorIndex = {
  id: string
  name: string // e.g. 'Product.description.external.3.cosine'
  sourceType: string // 'managed' | 'external'
  similarityFunction: string // 'cosine' | 'euclidean'
  dimensions: number
  // RushDB Cloud: 'pending' | 'indexing' | 'awaiting_vectors' | 'ready' | 'error'
  // Self-hosted engine: 'behind' until every record has a vector, then 'ready'
  status: string
  modelKey: string // the embedding model of a managed index; '' for an external one
}

type SchemaRelationship = {
  label: string // the label at the other end
  type: string
  direction: 'in' | 'out' // 'out': this label is the source
  count?: number // relationships of this type between the two labels
  properties?: Array<{
    name: string
    type: string
    relationshipsCount?: number
    // RushDB Cloud only: sample values or a range, as for record properties
    values?: Array<string | number | boolean>
    min?: number | string
    max?: number | string
  }>
}
```

## Caching

:::note Caching
On RushDB Cloud, both schema endpoints share one cached schema per project, kept for an hour. After that, a call still gets the cached schema straight away while a refresh runs in the background, so no call waits for a recalculation unless the project has no cached schema yet or you pass `force: true`. `force` waits for a schema that includes every write made before the call. With an SDK in direct mode there is no cache: each call reads the engine's catalog.
:::
