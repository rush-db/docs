# MCP tools

RushDB MCP exposes 53 tools on RushDB Cloud; in direct mode against a self-hosted engine, the 12 Cloud-only tools are not listed. Names below use the exact lower camel case identifiers published in the MCP manifest.

The connected MCP client receives the full JSON schema for each tool. This page is the quick reference for choosing the correct tool and understanding its main inputs.

## Safety levels

| Level       | Meaning                                                                    | OAuth scope     |
| ----------- | -------------------------------------------------------------------------- | --------------- |
| Read        | Retrieves or computes data without changing the data                       | `records:read`  |
| Write       | Adds data or changes state without overwriting existing values             | `records:write` |
| Destructive | Deletes or overwrites existing data; preview and confirm first             | `records:write` |

Every tool publishes a `title` and the MCP annotations `readOnlyHint`, `destructiveHint` and `openWorldHint`, plus `idempotentHint` where repeating a call has no further effect. The level above follows those annotations: Read tools have `readOnlyHint`, Destructive tools have `destructiveHint`. Updates count as destructive because they overwrite values, so clients that honor `destructiveHint` may ask you to confirm `updateRecord` or `updateRelation`, not only deletes. `syncConnection` is the only tool with `openWorldHint`, because it pulls data from an external source.

Over the hosted OAuth endpoint, a token granted `records:read` sees only the Read tools; a token granted `records:write` also carries `records:read` and sees every tool. See [Permissions](../../../connect/mcp.mdx#permissions).

An asterisk marks a required input.

## Discovery and properties

| Tool | Level | Main inputs | Purpose |
| --- | --- | --- | --- |
| `getSchemaMarkdown` | Read | `labels?`, `force?` | Return the complete graph schema as compact Markdown. Call once at session start. |
| `getSchema` | Read | `labels?`, `force?` | Return structured schema JSON, including property IDs and vector indexes. |
| `findLabels` | Read | `where?`, `limit?`, `skip?`, `orderBy?` | List or filter record labels and counts. |
| `findProperties` | Read | `where?`, `limit?`, `skip?`, `orderBy?` | Discover property names, types, IDs, and record counts. |
| `findPropertyById` | Read | `propertyId*` | Fetch metadata for one property. |
| `getSchemaSummary` | Read | `labels?`, `fewValues?` | Every label's properties with types, distinct counts, ranges and the values of small fields, in one read. |
| `searchValues` | Read | `text*`, `match?`, `labels?`, `limit?`, `minSimilarity?` | Find where a user-typed value is stored (label, property, exact spelling, count) across every property. |
| `resolveNames` | Read | `text*`, `limit?` | Suggest the real label or property behind a name that is not in the schema. |
| `propertyValues` | Read | `propertyId*`, `query?`, `orderBy?`, `limit?`, `skip?` | Return numeric or date ranges, or distinct string and boolean values. |
| `deleteProperty` | Destructive | `propertyId*` | Permanently remove a property and its values from all records. |
| `getSearchQuerySpec` | Read | none | Return the complete SearchQuery syntax reference. |
| `getQueryBuilderPrompt` | Read | none | Return the built-in discovery-first query builder prompt. |

## Records

| Tool | Level | Main inputs | Purpose |
| --- | --- | --- | --- |
| `findRecords` | Read | `labels?`, `where?`, `limit?`, `skip?`, `orderBy?`, `select?`, `groupBy?` | Search records and run grouped metrics queries. |
| `findOneRecord` | Read | `labels?`, `where?` | Return the first matching record for entity resolution probes. |
| `findUniqRecord` | Read | `labels?`, `where?` | Return exactly one matching record; fail when zero or multiple records match. |
| `getRecord` | Read | `recordId*` | Fetch one record by ID. |
| `getRecordsByIds` | Read | `recordIds*` | Fetch multiple records by ID. |
| `createRecord` | Write | `label*`, `data*`, `transactionId?`, `options?` | Insert or upsert one record. |
| `updateRecord` | Destructive | `recordId*`, `label*`, `data*`, `transactionId?` | Partially update one record while preserving unspecified fields. |
| `setRecord` | Destructive | `recordId*`, `label*`, `data*`, `transactionId?` | Replace all fields on one record. |
| `deleteRecord` | Destructive | `recordId*`, `transactionId?` | Delete one record by ID after previewing it with `findRecords`. |
| `deleteRecordById` | Destructive | `recordId*`, `transactionId?` | Delete one record by ID after previewing it with `getRecord`. |
| `bulkCreateRecords` | Write | `label*`, `data*`, `transactionId?`, `options?` | Insert or upsert multiple records with the same label; `options.mergeBy` and `options.mergeStrategy` control the upsert. |
| `bulkDeleteRecords` | Destructive | `labels?`, `where*`, `transactionId?` | Delete all records matching a query. Preview with `findRecords` first. |
| `exportRecords` | Read | `labels?`, `where?`, `limit?`, `orderBy?` | Export matching records as CSV. |

| --- | --- | --- | --- |
| `findRelationships` | Read | `where?`, `source?`, `target?`, `limit?`, `skip?`, `orderBy?` | Inspect edges. `where` filters edge type/properties; `source`/`target` filter endpoint records. |
| `attachRelation` | Write | `sourceId*`, `targetId?`, `targetIds?`, `relationType?`, `direction?`, `properties?`, `transactionId?` | Create relationships between existing records. |
| `updateRelation` | Destructive | `sourceId*`, `targetId?`, `targetIds?`, `relationType?`, `direction?`, `set?`, `unset?`, `types?` | Change or remove properties on existing relationships of one type. |
| `detachRelation` | Destructive | `sourceId*`, `targetId?`, `targetIds?`, `relationType?`, `direction?` | Remove relationships between records: every type unless `relationType` is given, both ways unless `direction` is. |

## Query rules

- Never guess labels or property names. Start with `getSchemaMarkdown`.
- Call `getSearchQuerySpec` before complex `findRecords` queries.
- Do not pass `limit` with `select`; it restricts the record scan and produces incorrect metrics.
- For a simple count, read `total` from `findRecords`.
- Preview and explicitly confirm destructive operations.
