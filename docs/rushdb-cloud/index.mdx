# RushDB Cloud

RushDB Cloud is the managed RushDB service at [app.rushdb.com](https://app.rushdb.com). It runs the RushDB engine for you and adds what the engine alone doesn't have:

- **the dashboard** — browse records and relationships, build queries, manage indexes;
- **projects, workspaces and team access**, with API keys per project;
- **managed embeddings** — mark a property for semantic search and Cloud embeds every write, and every text query;
- **AI features** — [natural-language search](../learn/search-query/smart-search.mdx) and [relationship-pattern suggestions](../learn/relationships/suggested-patterns.mdx);
- **the REST API** and a **hosted MCP connector** with OAuth for ChatGPT, Claude.ai and other web clients.

The engine itself — records, relationships, SearchQuery, keyword, vector and hybrid search, transactions — is the same one you can [self-host](../engine/getting-started/installation.md). Code written with the SDKs runs against both. See [What RushDB Cloud adds](./capabilities.mdx) for the full list.

## Get an API key

1. Sign up at [app.rushdb.com/signup](https://app.rushdb.com/signup) with your email address or a third-party provider.
2. Create a project in the dashboard.

   ![Create Project Button](/img/quick-start/create-project-screen.png 'Create a project')

3. Copy the API key from the project's Help page, or create more on the **API Keys** tab.

   ![Copy API Key](/img/quick-start/create-token-screen.png 'Copy an API key')

Then connect:

```typescript
import RushDB from '@rushdb/javascript-sdk'

const db = new RushDB(process.env.RUSHDB_API_KEY!)
```

### Full-access and read-only keys

- **Full access (read & write)** — the default. Can call every endpoint, including creates, updates, deletes, imports and transactions. **Server-side use only.**
- **Read-only** — can only query: record search and retrieval, labels, properties, relationship search, aggregations, keyword and semantic search, and CSV export. Every write is rejected with `403 Forbidden`.

A read-only key can't modify anything, so it is safe in client-side code for public demos and dashboards. Read-only is not private: anyone who extracts the key can read the project's data. Use read-only keys only for data meant to be publicly readable, and set an expiration where possible.
